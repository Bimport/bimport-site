# 4車種の名前・電話から相談する案（未公開）

既存BMW X1／Gクラス／124スパイダー／911を対象とした任意の画面案。標準の全車種フォームを切り替える実装ではない。`form.detailsOptional=true`と`form.contactFirst=true`が両方あるページだけ「ご連絡先→確認」の2段階になる。車種情報は引き継ぎ、必須は名前・電話。電話の代わりになる認証済み連絡方法が完成したとは扱わない。

## 入力と確認

初めに名前・電話を表示し、年式・距離・グレード/分類・都道府県はnative detailsの任意欄へ置く。省略した車両項目は、既存の実在する不明選択肢だけを使う。不明項目が設定にない場合は入力へ戻し、欄を開いて該当コントロールへフォーカスする。特定の年式・グレード等を推測しない。

確認から連絡先/車両情報を修正しても入力を保持。Enterだけで送らず、明示的な送信が必要。エラー表示を入力欄へ関連付け、段階変更のフォーカスとaria-currentを更新する。ヘッダー・固定CTA・買取の流れの「60秒」表現は、この案だけ無料相談の表現へ揃える。他ページの文言は変更しない。

写真は初回不要。写真の相談は既存公式LINEを案内するが、フォームとLINE案件を裏側で正式照合する機能をこの変更で作ったとはしない。受付番号をコピーしてLINEへ送る手順は追加していない。

## 送信・計測

送信payloadは既存GAS形式と同じ。名前/電話を検証し、確認後に値が変更された場合も再確認する。ページ表示から実際に5秒が過ぎるまで残り時間だけ待つ既存案を維持し、elapsedMsを偽らない。時間逆行・24時間超・送信先未設定なら送らず、入力を保持し、LINEと電話の代替を案内。自動再送はしない。既存の送信中guardを使う。

GASのok:trueが実通知/新規案件の保証ではないことは未解決。受領済みコードには無通知で同じ応答を返す条件があり、元担当の候補・本番版と照合が必要。GAS/DBの新しい重複受付処理・経費処理を作っていない。完了画面を実申込/接触/成約へ数えない。

新しい画面の操作イベントだけに固定文字列 `form_variant=contact_first_v1` を付ける。個人情報は含めず、未指定ページのイベント項目は維持。内部の確認イベントは従来どおりestimate_step=3で、画面の「STEP2」と同じ意味。単純な段階別件数差を離脱人数にしない。GA4でのcustom dimension登録・取得/受信・公開は未実施で、期間/対象/画面版を照合してから分析する。

## 確認コマンドと前提

標準buildを`dist`へ、ローカルの公開想定4車種版を別ディレクトリへ用意し、`HOME_PREVIEW_HTML=<標準build>/index.html CONTACT_FIRST_HTML_ROOT=<4車種公開想定build> node --test tests/*.test.cjs`。Node24/実Node22で69テスト。新しい最小入力suiteは41で、旧版23のケースは前のレビューpacketにも保持する。旧版・新案を重ねて適用しない。

通常870HTMLは元のまま、共通JS2資産の差分と新CSS1資産だけ。公開想定は4HTMLと共通JS2資産だけが変わる。実React/JS DOM・架空データ・模擬応答であり、実ブラウザ1440/375/320、Mac/iPhone、会社host、本番受付/通知/DB/LINEの証明ではない。画面確認と元担当/公開担当のレビュー、本人の具体的な公開承認の前に反映しない。

確認用ファイルでは実送信・電話/LINE移動を無効にする。実顧客の情報を入れず、架空データで入力→確認までを確認する。
