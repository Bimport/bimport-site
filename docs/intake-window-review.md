# 受付の時間条件に合わせる送信側の案（未公開）

受領GAS v3は、表示から5秒未満または24時間超のelapsedMsをok:trueで破棄します。先行4LPのoptionalDetails案には実時間を待つprepareEstimateがありますが、既存トップ/通常LPは直送経路でした。これは受領sourceとローカル時計の再現で、本番での障害発生の確認ではありません。

既存4LPの処理を使い、トップ/通常LPでも残りの実時間を待ち、送る直前に5秒〜24時間内かを再確認します。elapsedMsや日時を作り替えて通したり、GASの下限/上限・迷惑送信/重複処理を下げたりしません。正常に5秒以上経過した入力を余分に待たせません。時計が逆行した場合や期限超過では送らず入力を保持し、既存LINE/電話を案内します。自動再送はしません。

送信先未設定の通常LPで、送らずに完了表示へ進むデモ動作も取り除きます。送信先不明/応答不明/期限外では入力を残します。実際のメール到着・新規案件の登録は別で、GAS ok:true/generate_leadを実申込に数えません。

フォーム構造・必須電話・車種/詳細・受信先URL・通知先・GAS/DB・画像/実績は保持。JS参照の版名を20261126-received-windowへ揃え、古いJSのキャッシュが残らないようにする候補です。実際の配備/キャッシュ/ブラウザは公開承認後に確認します。

検証は架空の時計/入力・通信スタブを使います。通常の計測試験は6秒経過のfixtureへ直し、速い入力/期限外/タイムアウトは別の24試験で確認。単体/DOMの成功は実GAS/実機/本番受付の証明ではありません。新しい予約・課金API・受信側の重複防止やDB処理は作りません。

別途、既存トップの最大60/80/80文字と受領GASの30/30/40の相違があります。GAS上限候補85は未反映の別工程で、本案だけで長い車両情報の実受付まで解決したとは扱いません。公開/本番GAS変更・実通知は具体的な差分・検証・復旧を揃えて承認へ進めます。
